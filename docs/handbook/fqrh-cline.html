01 · Daily 5-Step Loop

Cline memisahkan kerja jadi dua mode: Plan (read-only) dan Act (eksekusi). Jangan minta Cline mengedit sebelum orientasi dan rencana disetujui.

01

ORIENT — Baca Context & Rules

Buka workspace yang benar. Minta Cline membaca AGENTS.md, .clinerules, struktur repo, dan git status tanpa mengedit file.

Orient yourself in this repository. Read the relevant AGENTS.md, .clinerules, README, project manifests, and git status. Do not edit any files. Summarize architecture, canonical patterns, test commands, and key risks.
02

PLAN — Mode Perancangan

Pakai Plan Mode untuk task medium/besar. Minta daftar file terdampak, alur data, edge cases, test commands, dan verification plan.

Start in Plan mode for [TASK]. Explore relevant files, identify dependencies, map symbols, edge cases, acceptance criteria, and verification commands. Do not modify files until approved.
03

ACT — Implementasi Terkendali

Setelah plan disetujui, pindah ke Act Mode. Ubah file dalam slice kecil, reuse pola yang sudah ada, dan hindari YOLO mode di repo utama.

Switch to Act mode. Implement only step [N] of the approved plan. Change only files in scope, add focused tests, preserve project conventions, and stop if assumptions are uncertain.
04

REVIEW — Checkpoint & Diff

Tinjau diff per batch. Manfaatkan Shadow Git Checkpoints untuk inspeksi atau rollback instan kalau hasilnya tidak sesuai.

Inspect the current checkpoint diff. Check correctness, security, edge cases, test coverage, and scope creep. Report findings by severity. Do not commit or push.
05

VERIFY — Buktikan dengan Output

Jalankan lint, typecheck, test, dan verifikasi UI/API. Laporkan output command aktual. Jangan klaim selesai tanpa bukti.

Run the test suite, lint, and typecheck for the affected modules. Report exact terminal command outputs, passing tests, remaining risks, and manual verification steps.

02 · Superpowers — Urutan Pemakaian

Ini bukan menu pilihan. Urutan di bawah adalah gate Cline 2026: dari pemisahan Plan/Act sampai beres-beres task tanpa mengotori context.

1. Plan → Act Separationmedium / large

Plan mode adalah sandbox analitis read-only. Act mode mengeksekusi rencana yang sudah disetujui. Jangan campur keduanya.

Start in Plan mode. Explore the relevant files and propose a minimal implementation plan. List files, exact symbols, edge cases, tests, and verification commands. Do not modify files until I approve.
2. /deep-planningarsitektur / refactor

Investigasi menyeluruh lintas modul plus pertanyaan klarifikasi sebelum baris kode pertama ditulis.

/deep-planning Explore the codebase systematically, identify dependencies, invariants, and risks, formulate a structured implementation plan, and ask any clarifying questions before switching to Act mode.
3. Shadow Git Checkpointssebelum Act

Snapshot otomatis sebelum setiap batch edit. Rollback 1-klik kalau slice-nya salah arah.

Create a clean checkpoint. Then proceed to implement only step 1 of the approved plan and pause for verification.
4. Context Mentionsefisiensi context

Pakai @file, @folder, @problems, @terminal, dan @git supaya Cline tidak mengunyah seluruh repo.

Inspect @problems and @file:src/auth/service.ts. Trace why the token refresh fails without altering other authentication flows.
5. Granular Auto-Approvaloperasi aman

Auto-approve hanya operasi read-only. Write, terminal, browser, dan MCP tetap minta konfirmasi.

Keep auto-approval limited to read-only file operations. Ask before any write, terminal, browser, or MCP action.
6. /cavemanhemat token

Mode komunikasi padat. Potong penjelasan, pertahankan path, error string, dan keputusan teknis.

/caveman full Keep technical precision, file links, and exact error strings verbatim. Compress explanations.
7. /newtaskganti task

Mulai task baru dengan ringkasan status, context bersih, dan referensi task sebelumnya — jangan tumpuk dua outcome di satu chat.

/newtask Summarize the current status, then start a fresh task for [NEXT OUTCOME] with a clean context.

06 · Menjaga Performa Cline

Cline lambat atau “lupa aturan” biasanya karena context kotor, rules kegemukan, YOLO aktif, atau dua task hidup di satu sesi.

1. Plan dulu, Act kemudian

Task multi-file atau berisiko selalu mulai di Plan Mode. Act hanya untuk slice yang sudah disetujui.

2. Checkpoint sebelum menulis

Shadow Git adalah jaring pengaman, bukan alasan untuk skip review. Lihat diff checkpoint sebelum lanjut slice berikutnya.

3. Mention yang sempit

Jangan lempar seluruh repo. @file, @folder, @problems, @terminal, @git menjaga context tetap relevan.

4. Compact / caveman saat sesi panjang

/compact atau /smol untuk task yang sama. /caveman memotong prosa. /newtask untuk outcome yang tidak berhubungan.

5. Rules pendek, skills on-demand

Rules yang gemuk dibaca setiap turn. Pindahkan prosedur panjang ke SKILL.md.

6. Auto-approve hanya read-only

Write, terminal, browser, dan MCP tetap manual. YOLO mode tidak dipakai di repo produksi.

7. Evidence sebelum “selesai”

Lint, typecheck, test, dan output terminal yang baru dijalankan. Klaim tanpa bukti adalah bug yang paling sering lolos.

8. Jangan bypass safety

Jangan commit secret. Jangan git push --force ke branch utama. Jangan hapus rekursif luas “supaya cepat”.
