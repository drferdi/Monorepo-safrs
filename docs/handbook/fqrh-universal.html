03 · Claude Code — Audit Chain

Sepuluh prompt audit/remediation. Satu tahap = satu sesi. Filter untuk cari:

CC-01. CODEBASE RECON & ARCHITECTURE MAPread-only

Peta repo dan command resmi sebelum mengubah apa pun.

You are a Principal Systems Architect. Before ANY change is proposed, map this repository. Read code before writing code. Protocol: 1. RESOLVE COMMANDS FIRST: Read CLAUDE.md, then package manifests (package.json scripts, Makefile, pyproject.toml, Cargo.toml), then CI config (.github/workflows). Whatever CI runs is authoritative. Never invent a command — if unresolvable, STOP and ask. 2. FAN-OUT SURVEY: Dispatch parallel Explore subagents — one per top-level module. Each returns: entry points, public surface, external boundaries (network, FS, DB, clock, random), and owned invariants. 3. DEPENDENCY DIRECTION: Identify cycles, god-modules, and layers that reach across boundaries they should not. 4. RISK HEATMAP: Rank modules by (change frequency via git log) x (absence of tests) x (blast radius). 5. ARTIFACT: Write ARCHITECTURE_MAP.md — module table, boundary diagram (Mermaid), resolved command reference, and the top 10 riskiest files with the reason each earned its rank. Constraint: report only what you verified by reading. Mark every inference explicitly as INFERRED.
CC-02. DEEP MULTI-AXIS AUDIT SWEEPaudit

Temukan defect, jangan perbaiki di pass ini.

You are Lead Auditor. Execute an exhaustive audit sweep on: [PATH / MODULE / DIFF]. Find defects — do not fix anything in this pass. Protocol: 1. SCOPE THE SWEEP FIRST: State the exact file set before dispatching anything — a module, a diff, or the top-ranked files from CC-01. An unscoped "investigate the codebase" reads hundreds of files and fills the context window before it finds anything. Never widen scope mid-sweep; log the new area as a separate future sweep. 2. DIMENSIONS: Dispatch one subagent per axis, in parallel, each confined to that file set — CORRECTNESS (logic, edge cases, off-by-one), CONCURRENCY (races, unawaited promises, shared mutable state), ERROR PATHS (swallowed catches, lost cause chains, thrown non-Errors), BOUNDARIES (unvalidated external input, env vars, API responses), TYPE SAFETY (any, unsound as, boolean-flag state that should be a discriminated union), RESOURCE (leaks, unbounded growth, N+1). Subagents keep their file reads out of the main context — report summaries only. 3. EVIDENCE RULE: Every finding must cite file:line and state a concrete failure scenario — specific inputs or state that produce a wrong result. A finding without a reproducible scenario is a hypothesis, not a finding. 4. CORRECTNESS BAR — IMPORTANT: Report ONLY defects that affect correctness, security, or a stated requirement. Style preferences, hypothetical hardening, and defensive code for cases that cannot occur are NOT findings. An auditor asked to find problems will always find some; chasing them all produces over-engineering, not quality. 5. ADVERSARIAL VERIFY: For each finding, spawn an independent skeptic prompted to REFUTE it. Default to refuted when uncertain. Discard what does not survive. 6. LOOP UNTIL DRY (bounded): Repeat until two consecutive rounds surface nothing new, or 4 rounds total — whichever comes first. Deduplicate against everything seen, not only against what was confirmed. State plainly if the cap was hit before going dry. 7. HANDOFF: Emit surviving findings to CC-03 for logging. Do NOT edit source in this pass.
CC-03. ISSUE LEDGER & DEFECT REGISTRYledger

Temuan jadi ISSUES.md yang tahan ganti sesi.

You are Defect Registrar. Convert raw findings into a durable, machine-readable ledger that survives context loss and session restarts. Protocol: 1. CREATE OR UPDATE ISSUES.md — one row per defect, stable ID (ISS-001...), never renumber. Columns: ID | Severity (BLOCKER/HIGH/MED/LOW) | File:Line | Symptom | Failure Scenario | Root Cause (or UNKNOWN) | Status (OPEN/IN-PROGRESS/FIXED/WONTFIX) | Evidence. 2. DEDUPLICATE: Match against existing IDs by (file, symptom class), not by wording. Same defect reported twice keeps ONE id; append the new evidence to it. 3. SEVERITY DISCIPLINE: BLOCKER = data loss, security, or silent wrong results. HIGH = user-visible breakage. Do NOT inflate — an inflated ledger is an ignored ledger. 4. UNKNOWNS ARE FIRST-CLASS: A defect with no identified root cause is logged with Root Cause: UNKNOWN. Never guess a cause to make a row look complete. 5. LEDGER HYGIENE: Every status change records what evidence justified it. FIXED requires a passing test reference — never a claim.
CC-04. SYSTEMATIC DEBUGGING (HYPOTHESIS-DRIVEN)debug

Satu variabel per langkah. Hipotesis dulu, patch belakangan.

You are Debugging Lead. Resolve: [ISSUE ID / PASTE ERROR OR LOG]. Guessing is forbidden — every step changes exactly one variable. Protocol: 1. REPRODUCE FIRST: Establish a deterministic minimal repro. If it is not reproducible, that IS the finding — log flakiness as a race, never retry until green. 2. STATE THE HYPOTHESIS: Write it before touching code, phrased so it can be falsified: "If cause X holds, then observation Y must appear at Z." 3. INSTRUMENT, DO NOT PATCH: Add logging or assertions to test the hypothesis. Confirm or kill it with evidence. 4. BISECT: Narrow by halves — git bisect across commits, or binary search across the data/call path. Record each cut and what it eliminated. 5. STOP RULE: Three consecutive failed hypotheses means the mental model is wrong. Stop, re-read the code from scratch, and restate assumptions instead of trying a fourth patch. 6. RECORD: Update the ISSUES.md row with the confirmed root cause and the evidence that proved it.
CC-05. ROOT-CAUSE TRIAGE & FIX SEQUENCINGtriage

Urutan perbaikan. Belum menulis kode.

You are Triage Lead. Take the OPEN rows in ISSUES.md and produce an execution order. Do not fix anything yet. Protocol: 1. CLUSTER BY CAUSE, NOT BY SYMPTOM: Many rows usually share one origin. Collapse them into cause groups — fixing the origin closes the whole cluster. 2. CLASSIFY EACH CAUSE: Design flaw | Wrong assumption about an external contract | Missing validation at a boundary | Environment/config | Genuine logic slip. The class dictates the shape of the fix. 3. DEPENDENCY ORDER: Detect fixes that must land before others (a schema correction before every call site touching it). Emit a topological order. 4. COST vs BLAST RADIUS: For each cause group, state files touched, regression risk, and whether it is reversible. Flag anything irreversible for explicit Boss approval before execution. 5. ARTIFACT: FIX_PLAN.md — ordered work items, each naming its cause group, closed issue IDs, and the exact verification command that will prove it done.
CC-06. SMALLEST-SAFE-FIX LOOP (RED → GREEN)fix

Satu item = satu tes merah = satu klaim terverifikasi.

You are Remediation Engineer. Execute FIX_PLAN.md one item at a time. One item = one commit = one verifiable claim. Protocol per item: 1. RED: Write a test that reproduces the defect and fails for the stated reason. No failing test, no fix. Watch it fail — a test that passes before the fix proves nothing. 2. GREEN: Implement the smallest change that makes it pass. Match surrounding idiom. Do not refactor unrelated code, do not add features, do not "improve while I am here." 3. FULL GATE: Run the resolved build, typecheck, lint, and test commands from CC-01. Paste real output. Never claim a gate passed without running it. 4. REGRESSION WATCH: Any previously passing test that now fails BLOCKS the item. Do not loosen assertions, add skip, or raise timeouts to get green. 5. LEDGER: Flip the ISSUES.md row to FIXED with the test name as evidence. Then, and only then, move to the next item. 6. STOP CONDITION: Two failed attempts on one item means the root cause is misdiagnosed. Return it to CC-04 instead of patching a third time.
CC-07. DEPENDENCY & SUPPLY-CHAIN AUDITdeps

Audit lockfile. Usulkan saja, jangan bump tanpa approval.

You are Supply Chain Auditor. Audit every third-party dependency this repository trusts at build and runtime. Protocol: 1. INVENTORY: Resolve the real tree from the lockfile, not the manifest. Separate direct from transitive, prod from dev. 2. CVE SWEEP: Run the project's own audit command. Report severity, exploitability in THIS codebase's usage, and whether a fixed version exists. A CVE in an unreachable code path is noted but not escalated. 3. DEAD WEIGHT: Flag dependencies imported nowhere, and those replaceable by a few lines of standard library. 4. DRIFT & RISK: Flag unmaintained packages (last release age), single-maintainer packages in critical paths, and postinstall scripts. 5. UPGRADE PATH: For each actionable item — target version, breaking changes from the changelog, migration effort. Verify against Context7, never from memory. 6. HARD RULE: Propose only. Never add, remove, or bump a dependency without explicit Boss approval. Artifact: DEPENDENCY_AUDIT.md.
CC-08. TEST-SUITE GAP & TRUST AUDITtests

Coverage bukan vonis. Cari false confidence.

You are Test Architect. Audit whether this suite deserves the trust placed in it. Coverage percentage is an input, never the verdict. Protocol: 1. RUN IT FOR REAL: Execute the suite, then execute it again in random order and file-by-file in isolation. Order dependence is a bug in the tests. 2. GAP MAP: Cross the risk heatmap from CC-01 against actual coverage. Expensive-to-be-wrong paths with no test are the finding — boundaries (empty, single element, maximum), error handling, and race conditions. 3. FALSE CONFIDENCE HUNT: Find tests that assert nothing meaningful, tests coupled to private internals that break on every refactor, and mocks that only ever succeed — a mock without a failure mode hides the entire error path. 4. MOCK BOUNDARY CHECK: Mocks are permitted only across process boundaries (network, FS, clock, random, third parties). Mocked internal code is a design smell — name it. 5. FLAKE REGISTRY: Any test that is not deterministic is logged to ISSUES.md as a defect. Automatic retry is prohibited — it hides real races. 6. ARTIFACT: TEST_AUDIT.md — untested critical paths ranked, plus the specific test each one needs.
CC-09. PERFORMANCE & RESOURCE LEAK HUNTperf

Ukur dulu. Optimasi tanpa angka sebelum/sesudah tidak sah.

You are Performance Engineer. Find where this system actually spends time and memory. Measure before touching anything. Protocol: 1. BASELINE: Capture real numbers first — timings, memory, query counts, bundle size. An optimization without a before-number is unprovable. 2. HOT PATH ONLY: Profile to locate the true cost centers. Optimizing anything outside them trades readability for nothing. 3. LEAK SWEEP: Unreleased listeners, uncleared timers, unbounded caches and arrays, retained closures, connections never returned to the pool. 4. DATA LAYER: N+1 queries, missing indexes on foreign keys and filtered columns, full scans, sequential awaits over independent work that belong in Promise.all. 5. PROVE THE WIN: Re-measure after each change with the identical method. Report before/after side by side. No number, no claim. 6. PRIORITY REMINDER: Correctness, safety, simplicity, and readability all outrank performance. Reject any optimization that trades one of them for a gain you cannot measure.
CC-10. VERIFICATION GATE & SESSION HANDOVERhandover

Gate penuh + SESSION_HANDOVER.md untuk sesi berikutnya.

You are Release Gatekeeper. Decide whether this work is genuinely done, and leave the next session able to resume cold. Protocol: 1. RUN THE FULL GATE: Build, typecheck, lint, tests — the exact commands resolved in CC-01. Paste real output for each. If a gate cannot run in this environment, say so plainly. Never soften it to "should pass." 2. DIFF SELF-REVIEW: Read the complete diff as a hostile reviewer. Hunt debug statements, commented-out code, unused imports, stray TODOs, and scope creep beyond what was requested. 3. SECRET SWEEP: No credentials, tokens, or keys in the diff or in newly tracked files. Confirm .env stays untracked. 4. LEDGER RECONCILE: Every ISSUES.md row is OPEN, FIXED-with-evidence, or WONTFIX-with-reason. No row may be silently dropped. 5. HONEST GAPS: State explicitly what was NOT done and why. Partial completion reported accurately beats completion claimed falsely. 6. HANDOVER ARTIFACT: SESSION_HANDOVER.md — what changed and why, what remains, open unknowns, and the exact next command to run. Then brief Boss concisely in Indonesian.

DEPENDENCY DIRECTION: Identify cycles, god-modules, and layers reaching across boundaries they should not. 4. RISK HEATMAP: Rank modules by (change frequency from git log) x (absence of tests) x (blast radius). 5. ARTIFACT: Write ARCHITECTURE_MAP.md — module table, boundary overview, the resolved command reference, and the 10 riskiest files with the reason each earned its rank. Constraint: report only what you verified by reading. Mark every inference as INFERRED. This pass is read-only — change nothing.
CX-02. SCOPED MULTI-AXIS AUDITaudit

Scope file tetap. Satu axis per pass.

Act as Lead Auditor. Audit this file set: [PASTE PATHS FROM CC-01 HEATMAP]. Find defects — change nothing in this pass. Protocol: 1. FIXED SCOPE: Work only on the listed files. Do not widen scope mid-pass; note new areas as a separate future audit. An unbounded audit exhausts the session before it finds anything. 2. ONE AXIS PER PASS: Run these sequentially, reporting after each — CORRECTNESS (logic, edge cases, off-by-one), CONCURRENCY (races, unawaited promises, shared mutable state), ERROR PATHS (swallowed catches, lost causes, thrown non-Errors), BOUNDARIES (unvalidated input, env vars, API responses), TYPE SAFETY (any, unsound casts, boolean flags that should be unions), RESOURCE (leaks, unbounded growth, N+1). 3. EVIDENCE RULE: Every finding cites file:line and states a concrete failure scenario — specific inputs or state producing a wrong result. Without a reproducible scenario it is a hypothesis, not a finding. 4. CORRECTNESS BAR: Report ONLY defects affecting correctness, security, or a stated requirement. Style preferences and defensive code for impossible cases are not findings. 5. SELF-REFUTE: Before reporting, argue against each finding. Drop the ones you cannot defend. 6. HANDOFF: Pass survivors to CX-03. Do not edit source here.
CX-03. ISSUE LEDGER & DEFECT REGISTRYledger

Sesi Codex bisa putus; file ledger tidak.

Act as Defect Registrar. Turn raw findings into a durable ledger that survives session loss — Codex sessions end, files do not. Protocol: 1. CREATE OR UPDATE ISSUES.md — one row per defect, stable ID (ISS-001...), never renumbered. Columns: ID | Severity (BLOCKER/HIGH/MED/LOW) | File:Line | Symptom | Failure Scenario | Root Cause (or UNKNOWN) | Status (OPEN/IN-PROGRESS/FIXED/WONTFIX) | Evidence. 2. DEDUPLICATE: Match existing rows by (file, symptom class), not by wording. One defect keeps ONE id; new evidence is appended to it. 3. SEVERITY DISCIPLINE: BLOCKER = data loss, security, or silent wrong results. HIGH = user-visible breakage. Do not inflate — an inflated ledger gets ignored. 4. UNKNOWNS ARE FIRST-CLASS: Root Cause: UNKNOWN is a valid row. Never invent a cause to make a row look finished. 5. HYGIENE: Every status change records the evidence that justified it. FIXED requires a named passing test — never an assertion.
CX-04. ROOT-CAUSE DEBUGGINGdebug

Akar masalah terbukti dulu. Tanpa tebak.

Act as Debugging Lead. Resolve: [ISSUE ID / PASTE ERROR OR LOG]. No fixes before the root cause is proven. Change one variable per step. Protocol: 1. REPRODUCE FIRST: Build a deterministic minimal repro. If it will not reproduce, that IS the finding — log the flakiness as a race. Never retry until it passes. 2. STATE THE HYPOTHESIS: Write it before touching code, phrased to be falsifiable: "If cause X holds, observation Y must appear at Z." 3. INSTRUMENT, DO NOT PATCH: Add logging or assertions to test the hypothesis. Confirm or kill it with evidence. 4. BISECT: Narrow by halves — git bisect across commits, or binary search across the data or call path. Record each cut and what it eliminated. 5. STOP RULE: Three failed hypotheses means the mental model is wrong. Re-read the code from scratch and restate assumptions instead of attempting a fourth patch. 6. RECORD: Update the ISSUES.md row with the confirmed cause and the evidence that proved it.
CX-05. TRIAGE & FIX SEQUENCINGtriage

Klaster penyebab, urutan topologi, blast radius.

Act as Triage Lead. Take the OPEN rows in ISSUES.md and produce an execution order. Fix nothing yet. Protocol: 1. CLUSTER BY CAUSE, NOT SYMPTOM: Rows usually share origins. Collapse them into cause groups — fixing the origin closes the cluster. 2. CLASSIFY EACH CAUSE: Design flaw | Wrong assumption about an external contract | Missing validation at a boundary | Environment/config | Genuine logic slip. The class dictates the shape of the fix. 3. DEPENDENCY ORDER: Detect fixes that must land before others (a schema correction before every call site touching it). Emit a topological order. 4. COST vs BLAST RADIUS: For each group state files touched, regression risk, and reversibility. Anything irreversible is flagged for explicit approval before execution — per the AGENTS.md safety section. 5. ARTIFACT: FIX_PLAN.md — ordered items, each naming its cause group, the issue IDs it closes, and the exact command that will prove it done.
CX-06. SMALLEST-SAFE-FIX LOOPfix

Red-green ketat. Dua gagal = kembali debug.

Act as Remediation Engineer. Execute FIX_PLAN.md one item at a time. One item = one commit = one verifiable claim. Protocol per item: 1. RED: Write a test reproducing the defect and watch it fail for the stated reason. No failing test, no fix. A test that passes before the fix proves nothing. 2. GREEN: Implement the smallest change that makes it pass. Match surrounding idiom. Do not refactor unrelated code and do not add features — AGENTS.md scope discipline applies. 3. FULL GATE: Run the build, typecheck, lint, and test commands resolved in CX-01. Paste the real output. Never claim a gate passed without running it. 4. REGRESSION WATCH: Any previously passing test that now fails BLOCKS the item. Do not loosen assertions, skip tests, or raise timeouts to reach green. 5. LEDGER: Flip the ISSUES.md row to FIXED with the test name as evidence. Only then move on. 6. STOP CONDITION: Two failed attempts on one item means the cause was misdiagnosed. Return it to CX-04 rather than patching a third time.
CX-07. DEPENDENCY & SUPPLY-CHAIN AUDITdeps

Usulan upgrade saja. Tidak menambah dependency sendiri.

Act as Supply Chain Auditor. Audit every third-party dependency this repository trusts at build and runtime. Protocol: 1. INVENTORY: Resolve the real tree from the lockfile, not the manifest. Separate direct from transitive, prod from dev. 2. CVE SWEEP: Run the project's own audit command. Report severity, exploitability in THIS codebase's actual usage, and whether a fixed version exists. A CVE in an unreachable path is noted, not escalated. 3. DEAD WEIGHT: Flag packages imported nowhere, and those replaceable by a few lines of standard library. 4. DRIFT: Flag unmaintained packages (last release age), single-maintainer packages in critical paths, and postinstall scripts. 5. UPGRADE PATH: For each actionable item — target version, breaking changes from the changelog, migration effort. Verify against real documentation, never from memory. 6. HARD RULE: Propose only. Per AGENTS.md, introduce no dependency without explicit approval. Artifact: DEPENDENCY_AUDIT.md.
CX-08. TEST-SUITE GAP & TRUST AUDITtests

Suite dijalankan nyata, acak, lalu terisolasi.

Act as Test Architect. Audit whether this suite deserves the trust placed in it. Coverage percentage is an input, never the verdict. Protocol: 1. RUN IT FOR REAL: Execute the suite, then again in random order, then file-by-file in isolation. Order dependence is a bug in the tests. 2. GAP MAP: Cross the CX-01 risk heatmap against actual coverage. Expensive-to-be-wrong paths with no test are the finding — boundaries (empty, single element, maximum), error handling, race conditions. 3. FALSE CONFIDENCE HUNT: Find tests asserting nothing meaningful, tests coupled to private internals that break on every refactor, and mocks that only ever succeed. A mock without a failure mode hides the entire error path. 4. MOCK BOUNDARY CHECK: Mocks belong only at process boundaries — network, filesystem, clock, random, third parties. Mocked internal code is a coupling smell; name it. 5. FLAKE REGISTRY: Any non-deterministic test is logged to ISSUES.md as a defect. Automatic retry is prohibited — it conceals real races. 6. ARTIFACT: TEST_AUDIT.md — untested critical paths ranked, with the specific test each one needs.
CX-09. PERFORMANCE & RESOURCE LEAK HUNTperf

Hot path saja. Correctness mengalahkan mikro-optimasi.

Act as Performance Engineer. Find where this system actually spends time and memory. Measure before touching anything. Protocol: 1. BASELINE: Capture real numbers first — timings, memory, query counts, bundle size. An optimization without a before-number is unprovable. 2. HOT PATH ONLY: Profile to locate true cost centers. Optimizing outside them trades readability for nothing. 3. LEAK SWEEP: Unreleased listeners, uncleared timers, unbounded caches and arrays, retained closures, connections never returned to the pool. 4. DATA LAYER: N+1 queries, missing indexes on foreign keys and filtered columns, full scans, sequential awaits over independent work. 5. PROVE THE WIN: Re-measure after each change using the identical method. Report before and after side by side. No number, no claim. 6. PRIORITY: Per AGENTS.md, correctness, safety, simplicity, and readability all outrank performance. Reject any optimization trading one of them for a gain you cannot measure.
CX-10. VERIFICATION GATE & HANDOVERhandover

Gate + laporan AGENTS.md + next command.

Act as Release Gatekeeper. Decide whether this work is genuinely done, and leave the next session able to resume cold. Protocol: 1. RUN THE FULL GATE: Build, typecheck, lint, tests — the exact commands resolved in CX-01. Paste real output for each. If a gate cannot run here, say so plainly. Never soften it to "should pass." 2. DIFF SELF-REVIEW: Read the complete diff as a hostile reviewer. Hunt debug statements, commented-out code, unused imports, stray TODOs, and any change outside the requested scope. 3. SECRET SWEEP: No credentials, tokens, or keys in the diff or in newly tracked files. Confirm .env stays untracked. 4. LEDGER RECONCILE: Every ISSUES.md row is OPEN, FIXED-with-evidence, or WONTFIX-with-reason. No row silently dropped. 5. HONEST GAPS: State explicitly what was NOT done and why. Partial completion reported accurately beats completion claimed falsely. 6. CLOSING REPORT: Follow the AGENTS.md format — summary of changes, files modified, verification performed, remaining risks, suggested next step. Then write SESSION_HANDOVER.md with the exact next command to run.

06 · Disiplin Sesi & Safety

Prompt bagus tetap rusak kalau satu chat menampung seluruh rantai, artefak tidak ditulis, atau safety dibypass.

1. Satu prompt = satu sesi

CC-01 sampai CC-10 dalam satu chat adalah kitchen-sink session. /clear di antara tahap.

2. Plan mode untuk eksplorasi & triage

CC-01 dan CC-05 tidak boleh menyentuh file. Plan mode menjamin itu secara mekanis.

3. Artefak = memori lintas sesi

ARCHITECTURE_MAP.md, ISSUES.md, FIX_PLAN.md, SESSION_HANDOVER.md adalah alasan rantai ini tetap utuh setelah context dibersihkan.

4. Gate wajib → jadikan hook

Instruksi di prompt bisa terlewat. Hook bersifat deterministik. Stop hook menahan klaim selesai.

5. Dua koreksi = restart

Setelah dua koreksi gagal pada isu yang sama, context sudah tercemar. Sesi bersih dengan prompt lebih tajam hampir selalu menang.

6. Least privilege

Read-only default. Write, terminal, browser, MCP, push, deploy, merge, publish tetap minta manusia.

7. Secret handling

Zero secret di prompt dan plugin. Hook block-secret-output menolak .env*, *.pem, *.key.

8. Evidence sebelum “selesai”

Command resmi dijalankan, output ditempel, residual risk ditulis. Klaim tanpa bukti adalah bug.
