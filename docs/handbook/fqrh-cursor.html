01 · Daily 5-Step Loop

Urutan Cursor setiap hari. Jangan minta Agent/Composer mengedit sebelum orientasi dan rencana terverifikasi.

01

ORIENT — Buka Root & Baca Aturan

Buka folder root workspace. Cek branch, working tree, .cursor/rules/*.mdc, dan task aktif. Belum mengedit.

Orient yourself in this codebase as a senior teammate. Read .cursor/rules/*.mdc, package manifests, main entry points, and git status. Trace canonical patterns, active tests, and architecture. Do not edit any files.
02

PLAN — Slice Kecil + Acceptance

Pecah jadi perubahan atomik: acceptance criteria, file terdampak, dan command verifikasi. Tunggu approval untuk task berisiko.

Create a minimal step-by-step implementation plan for [TASK]. Define acceptance criteria, exact files to modify, edge cases, tests to write, and verification commands. Wait for my approval.
03

IMPLEMENT — Eksekusi Slice

Kerjakan satu bagian kecil di Composer/Agent. Reuse abstraction yang ada. Jangan tambah dependency atau refactor yang tidak diminta.

Implement step [N] of the approved plan. Follow existing codebase conventions, keep changes atomic, reuse abstractions, and do not modify unrelated files.
04

VERIFY — Runtime + Test + Diff

Nyalakan server lokal bila perlu, jalankan test/lint/typecheck terdekat, lalu review setiap baris git diff.

Run the local development recipe if needed, then the narrowest relevant test suite, linter, and typecheck. Check the git diff for unintended changes. Report exact command outputs and manual verification evidence.
05

SHIP — Commit Terstruktur

Pastikan tidak ada secret atau file sementara. Conventional commit, evidence tercatat, push hanya setelah approval.

Review the final diff. Ensure no secrets, temp files, or console logs are included. Format a conventional commit (feat/fix/refactor) and list verified acceptance criteria. Do not commit or push until I approve.

02 · Superpowers — Urutan Pemakaian

Disiplin proses di Cursor: ikuti urutan ini supaya Agent tidak meloncat ke edit sebelum masalahnya jelas.

1. Brainstormmasalah masih kabur

Bandingkan opsi, asumsi, dan trade-off. Belum mengedit file.

Brainstorm this problem before coding. Identify constraints, unknowns, and 2–3 implementation options with trade-offs. Recommend one option, but do not edit files.
2. Spec / requirementsdefinisi

Ubah outcome jadi acceptance criteria yang terukur dan bisa dicek objektif.

Turn [TASK] into observable acceptance criteria, edge cases, and a definition of done. Do not edit files.
3. Planarsitektur

Task atomik: file, simbol, dependensi, risiko, verification command.

Write a minimal implementation plan for [TASK]. List exact files, symbols, risks, tests, and verification commands. Wait for approval.
4. Executeimplementasi

Slice demi slice di Composer/Agent, patuhi pola yang sudah ada di repo.

Implement only the approved slice. Reuse existing abstractions. Pause after this step for review.
5. Testvalidasi

Happy path, boundary, error handling, dan failure behavior. Jangan lemahkan tes supaya hijau.

Run or write the narrowest tests for happy path, boundary, and failure behavior. Report the actual output.
6. Reviewaudit diff

Review seperti senior engineer: correctness, security, data integrity, performa, scope creep.

Review the current diff as a skeptical senior reviewer. Report findings by severity with file:line evidence. Do not rewrite code yet.
7. Finishevidence & ship

Lint, typecheck, final test, catatan singkat, commit bersih setelah approval.

Finish with summary, files changed, commands run, remaining risks, and a conventional commit message. Do not push until I approve.

Decision rule

Kecil: Orient → Implement → Test → Diff.
Besar / berisiko: Brainstorm → Spec → Plan → Approval → Execute → Review.
Bug: Reproduce → Isolate fail 1 → Root cause → Regression test → Fix.

06 · Menjaga Performa Cursor

Cursor lemah biasanya karena rules gemuk, @Codebase dipakai untuk task sempit, satu chat menampung seluruh project, atau runtime tidak pernah dibuktikan.

1. Buka root, bukan file acak

Workspace = folder root. Baca README, manifest, .env.example, lalu install dependency di terminal Cursor.

2. Rules modular, bukan satu file raksasa

.cursor/rules/*.mdc dengan glob. alwaysApply hanya untuk aturan yang benar-benar selalu relevan.

3. Mention yang tepat

@Files/@Folders untuk task sempit. @Codebase hanya kalau lokasi belum diketahui. @Git sebelum review.

4. Satu chat = satu outcome

Jangan pakai satu Composer thread untuk seluruh project. Task baru, thread baru.

5. Dual terminal, cek port

Frontend dan backend di terminal terpisah. Port bentrok diselesaikan per-PID, bukan matikan semua proses.

6. Debug first failure

Breakpoint, Variables, Call Stack. Jangan tebak. Test gagal diisolasi dulu, baru difix.

7. Evidence sebelum “selesai”

Command resmi jalan, UI/API sesuai acceptance, lint/typecheck/test lolos, diff tanpa secret.

8. Jangan bypass safety

Jangan tempel API key ke prompt. Jangan commit .env. Jangan force-push ke branch utama.
