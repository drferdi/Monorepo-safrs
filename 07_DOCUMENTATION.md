# Documentation

## Purpose

This document defines how project knowledge should be documented and maintained to ensure long-term clarity and consistency.

## Core Principles

* Document decisions, not obvious code.
* Keep documentation concise.
* Maintain a single source of truth.
* Update documentation when knowledge changes.
* Prefer clarity over completeness.

## Guidelines

Documentation should explain:

* Why something exists.
* What problem it solves.
* Important design decisions.
* Known limitations.
* Future considerations, when relevant.

Avoid duplicating information across multiple documents.

If documentation becomes outdated, recommend updating it before introducing new explanations elsewhere.

## Expected Behavior

Documentation should remain accurate, discoverable, and useful for both humans and AI systems.
