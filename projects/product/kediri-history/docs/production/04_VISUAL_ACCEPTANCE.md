# 04 — VISUAL ACCEPTANCE
## Hard visual gates for Journey implementation

A scene is not accepted because build/tests pass.

A scene must pass frame, camera, light, historical-argument, copy, and handoff tests.

## Universal tests

### FRAME TEST
At representative scroll positions, the viewport must look deliberately composed, not like a normal web section.

### SUBJECT TEST
One dominant subject must be clear.

### CAMERA TEST
Scroll must imply directed movement through a world, not merely document position.

### LIGHT TEST
Light/material must do narrative work where appropriate.

### SILHOUETTE TEST
With text hidden, key scenes must remain distinguishable.

### HISTORICAL ARGUMENT TEST
Motion must communicate a historical idea.

### COPY TEST
Text arrives only when the frame is ready.

### HANDOFF TEST
The next scene emerges from an outgoing visual or conceptual element.

### HOLD TEST
At least one stable readable rest-state exists in every major scene.

## Automatic rejection

Reject the implementation if any of the following appears:
- centered cinematic box inside a large neutral page
- nested Journey scroll
- repeated title → paragraph → image template
- repeated fade-up choreography
- identical scene pacing
- unlabeled reconstruction
- hidden research uncertainty
- background scroll under timeline overlay
- broken direct anchor rest-state
- mobile as simple scaled desktop
- later scenes implemented before current batch approval
- historical text baked into a raster asset when it carries factual, chronological, geographical, evidentiary, or epistemic meaning (Authority Rule 1)
- interpretive or AI-generated imagery composed so it reads as documentary evidence or an authenticated object (Authority Rule 2)
- pseudo-script: glyphs made to look ancient that are not a correct transcription of a verified source (Authority Rule 3)
