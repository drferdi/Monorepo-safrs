## Design Target

The redesigned Diagnosis page should read as one clinical workspace:

1. **Clinical Context Strip**
   - Patient/RM/age/sex/pregnancy/allergies/chronic therapy context
   - Complaint summary and vital sign snapshot
   - No duplicated app header or brand shell
   - Compact only; must not consume more than one short section

2. **Diagnosis Reasoning**
   - Primary impression
   - Differential candidates
   - Red flags / do-not-miss items
   - Evidence supports, against, missing data, and suggested review
   - Selection state visible and limited to existing `MAX_DIAGNOSIS_SELECTION`
   - Insufficient-data state must not visually present R69 or any candidate as a confirmed diagnosis

3. **Therapy And Resep**
   - Diagnosis basis
   - Pharmacotherapy loading/error/ready state
   - Recommended medications and manual medications
   - Medication selection count
   - Alerts, guidelines, explainability, interactions if available

4. **RME Transfer**
   - Readiness state for diagnosis/resep/anamnesa
   - Auto fill, uplink diagnosis, uplink resep, uplink anamnesa, retry, cancel
   - Step status details remain accessible but not visually dominant

## Preservation Contract

This is a presentation-layer rewrite, not an engine refactor. The implementation must preserve these semantics exactly:

- Diagnosis scoring behavior remains unchanged.
- Candidate diagnosis generation and ranking remain unchanged.
- Evidence object shape and meaning remain unchanged.
- Confidence labels, confidence thresholds, and confidence-derived behavior remain unchanged.
- Insufficient-data logic remains unchanged and must stay visible in the UI.
- Manual diagnosis override remains available and keeps the same validation semantics.
- Manual medication entry remains available and keeps the same validation semantics.
- Bridge/canonical fallback behavior remains unchanged.
- Clinical safety semantics remain unchanged, including red flags, do-not-miss signals, missing evidence, and review-only pharmacotherapy.
- RME payload construction and transfer step semantics remain unchanged.

Only these surfaces are allowed to change:

- Visual grouping
- Information hierarchy
- Spacing
- CTA placement and labels
- Progressive disclosure
- Section ordering
- Empty/loading/error presentation

## Diagnosis Design Acceptance Contract

This is a design-only rewrite. Preserve all logic, state, handlers, thresholds, diagnosis ranking, pharmacotherapy behavior, manual entry behavior, RME transfer semantics, audit semantics, canonical fallback, and payload construction.

The new Diagnosis page must be visually simpler than the current page.

### Required Visual Hierarchy

1. **Clinical Context Strip**
   - Compact only.
   - Show patient, RM, age, sex, pregnancy, allergy, and chronic therapy summary.
   - Do not consume more than one compact section.

2. **Diagnosis Status / Primary Impression**
   - This is the main decision card.
   - It must answer:
     - Can diagnosis be locked?
     - What is the current primary candidate?
     - What is the confidence?
     - What is the safest next action?
   - For insufficient-data state:
     - Do not visually present R69 or any candidate as a confirmed diagnosis.
     - Primary CTA must be `Lengkapi Data Diagnosis` or equivalent.
     - `Setuju` must not be the dominant primary action.
     - Missing evidence must remain visible.

3. **Evidence Completeness**
   - Show evidence as compact checklist, not long paragraphs.
   - Use supports, against, missing, and review as grouped summaries.
   - Long reasoning must be behind progressive disclosure.

4. **Differential Candidates**
   - Show candidates as compact cards or rows.
   - Show confidence and selection state.
   - Advanced reasoning is collapsible.
   - Do not dump support/gap/review text directly into the main surface.

5. **Therapy + Resep**
   - Show only after diagnosis basis is clear.
   - Pharmacotherapy remains review-only and physician-gated.
   - Medication selection count must remain visible.
   - Manual medication entry must remain available.

6. **RME Transfer**
   - Keep transfer readiness and buttons accessible.
   - Transfer details may be collapsible.
   - Errors, running, partial, success, and failed states must remain visible.

### Visual Rules

- Single-column sidepanel-first layout.
- No duplicated app shell, header, or frame.
- Use existing Sentra tokens only.
- Use scoped `.diagnosis-*` classes only.
- Reduce borders and dense debug-console feel.
- No raw color strings.
- No visual overlap in buttons, badges, medication rows, or transfer rows.
- No section should look like developer logs unless explicitly expanded as advanced details.

### Safety Rules

- Insufficient data must be unmistakable.
- Red flags and do-not-miss items must never be hidden.
- Selected diagnosis, selected medications, and transfer readiness must always be visible.
- Doctor remains final decision maker.

## Risks

- Clinical workflow risk: a cleaner UI can hide review-critical data if sections are collapsed too aggressively. Keep red flags, selected diagnosis, selected medications, and transfer readiness visible.
- Regression risk: tests currently reference old labels. Update tests to behavior and section contracts, not cosmetic strings.
- Runtime risk: WXT may retain stale extension output. Always hard reload extension after rebuild.
- Scope risk: route navigation from workbench may be separately stale. If Diagnosis cannot be reached from the workbench, fix only the route prop pass-through as a separate mechanical task before judging the design.
