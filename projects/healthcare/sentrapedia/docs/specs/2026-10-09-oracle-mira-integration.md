# Oracle dan MIRA — cakupan disetujui

Authority: Gaffer “Okay integrate both oracle and MIRA” menyetujui arah perbandingan dan usulan integrasi pada 2026-10-09. Solo tanpa worker tambahan. R2 kontrak/server, R3 permukaan analisis klinis diotorisasi melalui permintaan integrasi; tidak mengubah isi/aturan klinis Oracle atau MIRA. Tidak melakukan inferensi berbayar dalam verifikasi.

Outcome: dialog Referensi & MIRA di sidebar, composer dan Command Center. Oracle dapat dicari nama/kode/kategori, ditampilkan verbatim dengan file/hash/ID dan status belum diverifikasi. Kategori berasal dari 15 nilai aktual; kode berulang tidak dideduplikasi. Semua empat file Oracle tetap utuh.

MIRA: form kasus fiktif terstruktur, tanpa auto-copy identitas Patient/Encounter atau narasi pasien. Kontrak v1 dilokalkan dari Med Assist, dengan atribusi. API Node lokal meneruskan ke layanan loopback yang sudah ada, token hanya environment server MIRA_SERVICE_TOKEN; default URL 127.0.0.1:8787, tanpa membaca env capsule lain. Same-origin POST, input/body/response validation, guard pola identitas, timeout/cancel dan satu permintaan aktif. Health GET tanpa panggilan model menampilkan reachable/configured terpisah. Submit memakai header synthetic agar batas awal data fiktif tetap.

Hasil: diagnosis kemungkinan/alternatif/jangan terlewat, alasan pendukung/penyangkal, informasi belum ada, langkah berikutnya, disposition dan unfilled. Tidak menganggap confidence angka sebagai probabilitas tervalidasi; tidak meresepkan dari narasi Oracle atau menghapus diagnosis MIRA di luar katalog. Oracle terkait hanya ditampilkan sebagai referensi kode persis, dapat banyak record. Kutipan PNPK halaman belum tersedia. Hasil berhasil dapat disimpan pengguna sebagai draf dengan source snapshot case/response/trace/waktu dan checklist wajib; edit/restorasi mengikuti gate workflow lama. Error tidak mengarang hasil atau fallback diagnosis.

Batas: token layanan belum diberikan dalam sesi ini; tampilkan kebutuhan konfigurasi secara jujur. Tidak memilih provider/model baru, membaca src/.env, mengubah Med Assist/MIRA, memasang native host, memulai server MIRA atau deploy. Mode simulasi hanya di tes, tidak hasil contoh otomatis di UI. Server inference hanya untuk akses lokal pengembangan; produksi memerlukan autentikasi/verifier dan peninjauan terpisah.

Acceptance: pencarian 144 record/15 kategori, provenance hash sesuai file, readonly; API menahan PII/invalid input/origin/response, abort/timeout/error sanitasi dan missing token; mocked response menampilkan semua bidang dan oracle match tanpa pemotongan; simpan menghasilkan draf/checklist/snapshot. Typecheck/lint/targeted tests/build/dry-run/extraction hash; browser desktop/mobile katalog/health/configuration/source/save bila hasil dari test tersedia. Live model tidak diuji dan tidak diklaim.
