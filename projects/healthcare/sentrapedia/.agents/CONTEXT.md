- Purpose: Sentrapedia clinical workspace with Indonesian UI and browser-local workflows in a standalone Next.js capsule.
- Stack: Next.js 16.4.0 / React 19.3.0 / TypeScript / Lucide / Vitest.
- UI: three-column Clinical Cockpit with collapsible navigation, rounded document canvas, and context/Timeline panel above 1200px; smaller screens use a panel dialog. Compact left-aligned home layout with four intent tabs above a reactive 180ms headline; four intent groups expose all 14 templates; slash picker, Focus Mode, and Command Center (Ctrl/Cmd+J) support navigation. Tosca (#40E0D0), Arial/Helvetica, wordmark shadow are preserved; the promotional panel has been removed at Gaffer's request. Responsive navigation drawer at 760px and below.
- Localization: Indonesian interface and default document language; English medical/technical terms and saved language preferences are preserved. Source text and stored records are never translated in place.
- Motion: reusable `components/sidebar-submenu.tsx` folds one section at a time with an active branch; `components/pixel-loader.tsx` cycles four pixel patterns and supports completion/reduced motion. Used by route/startup, context reading, clipboard, microphone startup, and composer busy UI. Local drafting is synchronous and has no artificial waiting.
- Data: `lib/workspace.ts` owns typed patient/list/encounter/message state and persistence validation. Optional v1 message metadata stores source snapshots, original content, and local draft/reviewed/final status. Editing resets status to draft; final requires reviewed. Legacy records stay readable; absent source snapshots remain unavailable. `lib/studio.ts` owns presentation helpers; `components/workspace.tsx` coordinates interactions.
- Drafting: `lib/note-structure.ts` organizes explicit labels and speaker statements. `lib/drafts.ts` builds 14 clinician-review templates without clinical inference or external AI.
- Safety boundary: fictional data only, unencrypted browser storage, optional existing MIRA service for explicitly entered fictional cases; no guideline-validation claims. Browser speech recognition is optional and may use the browser vendor's speech service.
- Contracts and verification: see `capsule.json`, `README.md`, and `.agents/HANDOFF.md`.
- Keep all runtime/build/test/deployment dependencies inside this capsule; root is optional governance only.

- Document Studio: section navigation/editing, full-document editing, source comparison, and before/current comparison. Status is user-controlled local metadata, not clinical approval or an audit trail. Context uses explicit source labels; missing facts are never inferred. Timeline filters by Patient, with unlinked Encounters kept separate.
